The sample run

One event. One receiver. Three allowed attempts.

Ready. Takes about four seconds.

  1. Abandoned jobWorker A claims the event, then leaves it unfinished.
  2. Lease expiresWorker B waits for the one-second lease before taking over.
  3. Receiver recoversThe receiver fails twice with HTTP 503, then accepts the event.

Uses the actual Python service and worker with a fixed, in-process receiver.

What this verifies

A completed run must leave one receiver record and one delivery after the producer submits the same event again. A failed assertion is shown as an error.

Each run gets a temporary SQLite database that is removed afterwards. This demo makes no outbound webhook calls and does not host a persistent queue. PostgreSQL concurrency and HTTPS delivery have separate tests in the repository.
